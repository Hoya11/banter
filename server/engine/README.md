# engine: 3자 대화의 공통 로직과 평가

사용자 1명과 AI 2명의 화자 선정, 페르소나, 발화 생성과 평가를 담당한다.
현재 구조와 선택은 [문제 해결 사례](../../docs/project-walkthrough.md)와
[설계 결정 기록](../../docs/decisions.md)에 정리. 초기 설계는
[엔진 설계 v0.1](../../docs/engine-design-v0.1.md)에 보존.

| 경로 | 현재 역할 |
| --- | --- |
| `graph/` | 공통 상태, 화자 규칙, 프롬프트와 발화 후처리 및 평가용 LangGraph 구성 |
| `personas/` | 대표 듀오 1쌍의 말투, 성향과 목소리 설정을 데이터로 관리 |
| `eval/` | 시나리오 실행, judge 채점과 추적 및 공급자 어댑터 |

LangGraph는 [평가 하네스](eval/harness.py)에서 시나리오의 AI 턴을 실행한다.
v1은 화자 선정, 대사 생성과 상태 갱신을 나누고, v2는 화자 선정과 대사를 한 호출에
생성한 뒤 상태를 갱신한다. [실시간 API](../api/app.py)는 이 그래프를 실행하지 않고
공통 상태와 프롬프트 함수를 직접 조합하며, WebSocket 입력, LLM 생성과 TTS 작업을
`asyncio`로 관리한다. 끼어들기 취소와 오래된 오디오 폐기도 실시간 API와 브라우저의 역할이다.

현재 서버 진입점은 v2 통합 생성을 사용한다. v1은 비교와 별도 실행 경로로 보존하며,
v2 헤더 오류 시에는 추가 supervisor 호출 없이 기계적으로 화자를 교대한다.
평가 방식은 [평가 하네스 설명](eval/README.md)을 참고한다.

현재 전송은 WebSocket이며, 브라우저 VAD는 push-to-talk와 별도로 선택하는 옵션이다.
WebRTC 또는 LiveKit은 실제 측정에서 전송 지연, 지터나 에코가 병목으로 확인될 때
검토할 후속 대안이다. 우선 현재 경로의
끼어들기 품질과 오류 복구를 검증하고, [실험 기록](../../docs/experiments/README.md)에
관찰과 한계를 남긴다.
