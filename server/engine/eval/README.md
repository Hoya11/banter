# 대화 평가

고정 시나리오로 대화를 만들고, 별도의 LLM이 루브릭에 따라 텍스트를 채점한다.
화자 선택과 생성 방식의 변경을 비교하는 내부 평가이며, 실제 음성 지연이나 사람의 만족도를
직접 측정하지 않는다. 결과와 정정 이력은 [실험 기록](../../../docs/experiments/README.md)에 있다.

## 구성

| 파일 | 역할 |
| --- | --- |
| [harness.py](harness.py), [scenarios.yaml](scenarios.yaml) | LangGraph로 AI 턴을 실행하고 사용자 참여, 침묵과 개입 시나리오를 적용 |
| [judge.py](judge.py), [rubric.yaml](rubric.yaml) | 대화와 중단 표시를 평가 프롬프트에 담고 항목별 점수와 근거를 요청 |
| [schema.py](schema.py), [scoring.py](scoring.py) | 출력 구조를 검증하고 평균 7.0 이상, 최저 6 이상이라는 내부 기준으로 판정 |
| [tracing.py](tracing.py) | 설정 시 Langfuse에 평가 대화와 점수를 기록. 키가 없으면 외부 기록 생략 |
| [providers.py](providers.py), [elevenlabs.py](elevenlabs.py) | 평가와 실시간 API가 함께 사용하는 공급자 어댑터 |

실시간 입력, 생성 취소와 오디오 무효화는 [API](../../api/app.py)가 asyncio로 처리한다.
이 평가 그래프에서 주입하는 개입은 텍스트 시나리오이며 실제 브라우저의 재생 위치와 같지 않다.

## 결과를 읽는 기준

- GO는 프로젝트에서 정한 내부 임계값을 통과했다는 뜻이다.
- 통합 생성 비교는 시나리오별 3회 기록이다. 항목별 결과는 엇갈리며 통계적 우위는 미검증.
- 초기 끼어들기 점수는 평가 입력 오류로 무효화한 뒤 수정하고 재측정했다.
  [오류와 수정 근거](../../../docs/project-walkthrough.md#사례-3-끼어들기를-평가하지-못한-테스트-수정)
- 자동 테스트는 가짜 공급자를, 평가 시나리오 실행은 실제 LLM을 사용한다.
  자동 테스트는 [루트 안내](../../../README.md#자동-테스트)를 따른다. 실제 평가 호출은
  결제 상태, 지출 상한, 키와 예상 호출 범위를 확인한 뒤 실행한다.
