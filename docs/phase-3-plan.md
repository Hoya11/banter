# Phase 3: 음성 참여 구현과 검증 계획

목표: 사용자 발화 종료부터 첫 오디오 응답까지 p95 1.5초 미만과 자연스러운 끼어들기.
현재 달성 수치는 아니며, 과거 관찰은 [지연 기록](experiments/latency.md)에 보존.

## 구현 상태

| 항목 | 현재 상태 | 검증 범위 |
| --- | --- | --- |
| 문장별 TTS | 완성된 문장부터 합성·전송 | 순서와 늦은 결과 폐기 회귀 |
| 스트리밍 STT | 24 kHz PCM 전송, 명시적 commit, 최종 전사 반영 | 모의 공급자로 전송·취소·복구 검증. 실제 연결·전사는 미확인 |
| VAD 선택 모드 | 말 시작·종료 감지와 기존 hold·commit 경로 연결 | 소음 후보, 짧은 침묵, 중간 절단과 늦은 이벤트 모의 검증 |
| 사전 생성 대기 | 입력과 준비 완료의 동시 대기, 입력 우선 처리 | 입력 경합과 취소 회귀 |
| 재생 중단 이력 | 발화 ID로 중단 표시, 이전 이력의 사전 생성 결과 폐기 | 생성 완료·사전 생성·ACK 시간 초과 회귀 |
| 전사 연결 점검 | 음성 전송 없이 연결·설정만 확인하는 명령 | 가짜 공급자 검증 완료. 원격 실행 미실시 |

기본값은 push-to-talk와 파일 전사. 스트리밍 STT와 VAD는 [실행 설정](../README.md#실행)으로 선택.
전송은 WebSocket 유지. VAD는 버튼 조작을 줄이기 위한 옵션이며 지연·인식률 개선 효과는 측정 전.

## 실환경 검증 순서

1. [전사 연결 점검](../server/README.md#전사-연결-점검): `4000` 오류의 설정·진단 보강 후 연결과 설정 응답 확인.
2. 기본 음성 흐름: 정상 전사, AI 재생 중 끼어들기, 오류 후 재입력과 세션 재시작 확인.
3. 파일 전사와 스트리밍 전사 비교: push-to-talk와 문장·기기를 고정하고 공급자·모델 차이 기록.
4. VAD 비교: 스트리밍 STT를 고정하고 헤드폰·스피커 조건별 오감지, 놓친 발화와 중간 절단 집계.

측정 전 결제 상태, 지출 상한, 키 설정 여부와 호출할 세션·발화 수 확인.
감지 시점과 실제 발화 시점, 브라우저 pause 적용과 실제 출력 중단은 각각 별도 지표로 기록.
모의 시간과 테스트 성공 건수는 실제 지연·정확도 수치로 사용하지 않음.

[PTT 기준 측정](experiments/push-to-talk-baseline.md) / [STT 비교](experiments/streaming-stt-ab.md) / [VAD 비교](experiments/vad-interruption.md)

## 다음 개발 범위

우선순위는 현재 구현의 실환경 검증과 발견한 오류 보완. 다음 항목은 후속 개선 후보.

- 음성 인식 실패 후 제한된 재시도 대기: 현재는 발언권을 해제하고 AI 대화 재개.
- API 모듈의 책임 분리: 연결 처리와 대화 세션 제어를 기존 회귀 테스트를 유지하며 분리.
- 단어별 청취 구간 추정은 범위 제외. 현재 이력은 생성된 전문과 중단 표시를 보존.

WebRTC·LiveKit은 전송 지연, 지터 또는 에코가 실제 병목으로 확인될 때 검토.
의미 기반 턴 종료는 짧은 침묵과 발화 완료를 구분하지 못하는 문제가 남을 때 검토.
현재 수정 근거는 [문제 해결 사례](project-walkthrough.md), 완료된 회귀는
[사전 생성](../server/tests/test_prefetch.py)과 [재생 이력](../server/tests/test_playback_history.py)에 연결.
