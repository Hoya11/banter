# Phase 3 실행 계획: 실시간 음성 참여와 끼어들기

목표는 유저 발화 종료 후 첫 오디오 p95 1.5초 미만과 자연스러운 끼어들기입니다.
이는 달성한 성능이 아닌 목표입니다. 기존 지연 관찰은
[지연 기록](experiments/latency.md), 현재 단계의 실제 비교 조건은 각 실험 문서에서 확인합니다.
전송 계층과 관계없이 적용할 수 있는 개선부터 진행하고, push-to-talk 기준선을 보존합니다.

## 3a. 문장 단위 TTS 스트리밍

- 첫 문장이 완성되는 즉시 합성과 전송을 시작하고 나머지 문장은 재생 중 차례로 합성합니다.
- 발화 전체 생성과 합성이 끝나기를 기다리는 구간을 줄입니다.
- 브라우저는 문장 재생과 자막을 동기화하고, 끼어들면 재생과 대기열을 중단합니다.

## 3b. Push-to-talk 스트리밍 STT

- 버튼 입력은 유지하고 말하는 동안 24 kHz PCM을 전송합니다.
- 버튼을 놓으면 잔여 PCM을 전송한 뒤 입력을 명시적으로 commit합니다.
- 최종 전사만 대화와 LLM 입력에 반영하며, 요청 ID로 늦은 결과를 격리합니다.
- 기존 파일 전사를 유지하고 같은 조건에서 지연과 정확도를 비교합니다.
- 코드와 가짜 공급자 테스트가 있다는 사실을 실제 API 성능 검증과 구분합니다.
- 측정 계획은 [스트리밍 STT 비교](experiments/streaming-stt-ab.md)에 기록합니다.

## 3c. VAD 선택 모드

AI 둘의 대화를 듣다가 버튼을 매번 조작하지 않고 말로 참여하는 경험이 목적입니다.
버튼 조작 때문에 실제 사용자가 얼마나 불편했는지, 자동 감지가 얼마나 개선하는지는 아직
측정하지 않았습니다. VAD는 이미 구현한 버튼 이후 재생 중단이나 STT 지연 개선의 대체물이
아니며, 자동 감지의 편의와 오감지 비용을 비교하는 실험입니다.

- 기본값은 push-to-talk로 유지합니다. `BANTER_INTERACTION_MODE=vad`와
  `BANTER_STT_MODE=streaming_push_to_talk`를 함께 설정하면 서버 capability로 VAD를 선택합니다.
- 마이크 켜기와 끄기는 사용자가 명시적으로 조작합니다. 켜진 동안 브라우저에서 말 감지를 수행합니다.
- Silero v5를 브라우저에서 실행하며, 모델과 실행 파일은 버전을 고정해 로컬 서버에서 제공합니다.
- 청취 상태와 발화 감지 상태는 버튼의 눌림 상태에서 분리합니다. 발화별 요청 ID, `hold`,
  브라우저 재생 중단, PCM 전송, commit, 오류 복구와 늦은 이벤트 검사는 기존 경로를 공유합니다.
- 침묵 중에는 STT 공급자에 오디오를 계속 전송하지 않습니다. 발화와 직전 버퍼만 발화 요청으로 보냅니다.
- 초기 설정은 말 시작 확인 160 ms, 종료 침묵 600 ms, 발화 직전 버퍼 256 ms입니다.
  정확도가 입증된 최적값이 아닌 실험 시작값입니다. 발화가 12초에 도달하면 확정하지 않고 취소한 뒤
  감지를 다시 준비하여 기존 서버의 15초 제한을 보존합니다.
- 소음 오감지, 짧은 침묵, 중간 절단, 지연된 감지 이벤트와 재시작 경계를 테스트합니다.
- 이 모델은 사용자 본인의 목소리를 식별하지 않습니다. 주변 발화와 AI 스피커 음성 유입도 확인합니다.
- 대안과 측정 결과는 [VAD 끼어들기 실험](experiments/vad-interruption.md)에 남깁니다.
- 같은 판단 코드를 사용하는 [녹음 평가 도구](experiments/vad-recording-evaluation.md)로
  종료 설정을 비교합니다. 수동 라벨 기반 녹음 지표와 실제 대화의 지연·에코 평가는 구분합니다.

## 3d. 측정 후 전송 계층 검토

현재 WebSocket에서도 말 감지에 따른 자동 끼어들기를 구현할 수 있습니다. 먼저 VAD의 사용자
체감 효과와 실패 사례를 확인합니다. 전송 지연, 지터 또는 에코가 실제 병목으로 확인되면
WebRTC나 LiveKit 도입의 효과와 이전 비용을 비교합니다. WebRTC 도입 자체를 다음 단계의
완료 조건으로 삼지 않으며, 도입만으로 에코나 잘못된 발화 판정이 해결된다고 가정하지 않습니다.

의미 기반 턴 종료는 짧은 침묵과 완결된 발화 구분이 실제 문제로 남을 때 검토합니다.
말이 있는지 감지하는 기능과 말이 끝났는지 판단하는 기능을 구분합니다.

## 검증과 마무리

- 같은 기기와 시나리오에서 파일 전사, 스트리밍 push-to-talk, VAD를 비교합니다.
- 감지 시점 기준 지연과 실제 발화 시작 및 종료 기준 지연을 분리합니다.
- 브라우저 pause 적용과 실제 스피커 출력 중단을 분리합니다.
- 가짜 시간, 가짜 발화 확률과 테스트 성공 건수를 실제 성능 수치로 사용하지 않습니다.
- OpenAI 또는 ElevenLabs 호출 전에 결제 상태, 지출 상한, 필요한 키와 예상 호출 범위를 설명합니다.
- 문제, 선택한 구조, 대안, 개선 전후 측정과 남은 실패 사례를 `docs/experiments`에 기록합니다.
- 이번 포트폴리오 산출물은 README, [문제 해결 사례](project-walkthrough.md), 설계 결정과 실험 기록입니다.
  코드와 회귀 테스트로 설명을 연결하며 데모 영상 제작은 범위에서 제외합니다.
  영상 제작 여부와 실제 음성 검증은 별개이며, 측정하지 않은 항목은 미확인 상태로 남깁니다.
- 커밋과 푸시는 명시적으로 요청받은 경우에만 진행합니다.

## 다음 개발 범위

미완료 사전 생성 대기의 입력 지연은 수정하고 회귀 테스트를 추가했습니다. 입력과 준비 완료가
겹치면 입력을 우선하며, 말 시작은 기존 전사 대기로 인계하고 새 입력이 확정되면 이전 결과를
폐기합니다. 연결 종료와 세션 취소 경계도 가짜 공급자로 검증합니다.
[재현과 수정 기록](project-walkthrough.md#미완료-사전-생성-대기의-입력-지연)은 실제 지연 측정과 구분합니다.

다음은 API 모듈에 집중된 연결 처리와 대화 세션 제어의 책임을 나누는 작업입니다.
전체 구조를 한 번에 교체하지 않고 기존 동작과 선택 모드를 보존합니다.

음성 인식 실패 시 현재는 발언권 대기를 해제하고 기존 AI 재개 흐름으로 돌아갑니다.
사용자에게 제한된 재시도 시간을 주고, 입력이 없으면 대화를 재개하는 정책을 후속으로 검토합니다.
이는 아직 구현하지 않은 조작 흐름 개선이며 음성 인식 정확도 개선과는 구분합니다.

생성이 끝난 AI 발화나 사전 생성한 발화는 재생 도중 끊겨도 전체 텍스트가 이력에 남을 수 있습니다.
완성된 발화에도 재생 중단 여부를 반영하는 범위부터 검토하며, 단어별로 실제 들은 위치를 추정하는
기능까지 같은 작업에 포함하지 않습니다. 두 작업은 가짜 공급자와 재생 이벤트로 검증할 수 있습니다.
