# Phase 1 실행 계획 — banter

이 문서는 착수 당시 계획을 보존한 자료이며 체크박스는 현재 완료 현황이 아니다.
현재 구현과 검증 범위는 [README](../README.md), 후속 작업과 포트폴리오 범위는
[Phase 3 계획](phase-3-plan.md)을 기준으로 확인한다.

> Phase 1(텍스트 3자 엔진 + 평가) 착수 체크리스트.
> PRD §3·엔진설계 §4의 구현 순서에 확정 결정(D-005~D-008)을 반영한 실행 단위.
> 원칙: 평가 기준(A)을 제품 코드(B·C)보다 먼저 못박는다 — 기준이 나중이면 만든 걸 정당화하는 방향으로 휜다.

## 순서 의존성 (한눈에)
```
A. 평가 기준 ──► B. 엔진 골격 ──► C. 페르소나·대화 ──► D. 끼어들기·판정
   (루브릭/컷/스키마는 먼저 확정, 실제 자동 채점은 C의 대화가 생긴 뒤 D에서 수행)
```

## 0. 착수 준비
- [ ] `git init` + 문서 확정본 첫 커밋
- [ ] 레포 스캐폴드 — `web/` · `server/api/` · `server/engine/` 모듈 경계 (PRD §6.2, Phase 3 물리분리 대비)

## A. 평가 기준 먼저 ⭐ (엔진설계 §4의 0번 — 코드보다 선행)
- [ ] judge 루브릭 v1을 **설정 파일**로 (5항목, 엔진설계 §4.1) — D-005 인터페이스
- [ ] judge 출력 스키마 고정 + `judge()` 함수 골격 (단일 심판)
- [ ] go/no-go 컷 상수화 (평균 ≥ 7.0 & 최저 항목 ≥ 6.0) — D-006
- [ ] Langfuse 연동 (trace + experiments 뼈대)

## B. 엔진 골격
- [ ] LangGraph 상태 스키마 (엔진설계 §1.1)
- [ ] 노드 그래프 골격 — 발화 생성은 스텁 (§1.2, v1 기준)
- [ ] 화자 선정 v1 supervisor + 규칙 가드 (§1.3)
- [ ] LLM provider 추상화 + 1종 연결 (2~3종 비교는 후속 — PRD §6.5)

## C. 페르소나 & 대화  〈본인 창작 필요〉
- [ ] 대비형 듀오 페르소나 **설정 스키마** (D-007) — 이름/말투/스탠스/화제성향/보이스ID(자리만)
- [ ] 페르소나 프롬프트 초안 연결 → 수동 대화 테스트 (루브릭으로 자가 채점)
- [ ] 라디오 모드 (침묵 타이머 → AI 턴 재진입, §1.2)
- [ ] 스트리밍 채팅 UI + 입력창 상시 활성 (텍스트 barge-in 전제, §2.1)

## D. 끼어들기 & 판정
- [ ] 텍스트 끼어들기 (생성 태스크 취소 + `interrupted` 기록 + 수습, §2.1)
- [ ] 평가 시나리오 셋 v1 (끼어들기/화제전환/침묵/소외 각 3~5케이스)
- [ ] judge 자동 채점 하네스로 시나리오 셋 채점
- [ ] **go/no-go 판정** (컷 대조) → 결과를 decisions/failures에 기록

- PostgreSQL 영속화 → 인메모리로 진행 (D-008)
