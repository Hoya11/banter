# 지연 측정 (엔진설계 §3)

> 측정 항목: 발화 재생 완료(played ack) → 다음 발화 오디오 도착 간격.
> AI끼리의 티키타카 체감을 좌우하는 핵심 구간이다.

## 2026-08-25 — prefetch(§3.2) 도입 전후

환경: gpt-5.6-luna(발화) + gpt-4o-mini(supervisor) + ElevenLabs v3(TTS), 로컬 WS 실측 3턴.

| 구성 | 발화 간 간격 | 비고 |
|---|---|---|
| prefetch 없음 (직렬) | ~8s | radio 5s + supervisor ~1s + 생성 ~1.5s + v3 합성 2~4s |
| **prefetch (병렬)** | **평균 2.09s** (1.52 / 2.88 / 1.87) | radio 틈 1.5s 포함 — 실제 준비 지연 ~0.6s, 최고 히트 0.02s |

### 구조
- 발화 A가 재생되는 동안 백그라운드에서 다음 턴(화자선정→대사→합성)을 완성해 둔다.
- 유저 개입 시 폐기 후 실시간 경로로 반응 (비용: LLM+TTS 1회 낭비).
- 재생 페이스는 FE played ack 기반 — 서버가 재생보다 앞서 달리지 않음.

### 관찰
- **준비 지연이 재생 시간 뒤에 숨어 체감 0에 수렴** — PRD가 "이 구조만의 이점"으로 예고한 그대로.
- 2.88s 케이스는 v3 합성이 재생(3s 가정)보다 오래 걸려 일부 노출된 것 — 발화가 길수록 재생도 길어져 자연 상쇄되는 경향.
- 남은 간격의 대부분은 의도된 유저 발언 틈(radio 1.5s) — 티키타카 리듬 튜닝 변수.
