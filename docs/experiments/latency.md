# 지연 측정 (엔진설계 §3)

> 측정 항목: 발화 재생 완료(played ack) → 다음 발화 오디오 도착 간격.
> AI끼리의 티키타카 체감을 좌우하는 핵심 구간이다.

## 2026-08-25 — prefetch(§3.2) 도입 전후

환경: gpt-5.6-luna(발화) + gpt-4o-mini(supervisor) + ElevenLabs v3(TTS), 로컬 WS 실측 3턴.

| 구성 | 발화 간 간격 | 비고 |
|---|---|---|
| prefetch 없음 (직렬) | ~8s | radio 5s + supervisor ~1s + 생성 ~1.5s + v3 합성 2~4s |
| **prefetch (병렬)** | **평균 2.09s** (1.52 / 2.88 / 1.87) | radio 틈 1.5s 포함 — 실제 준비 지연 ~0.6s, 최고 히트 0.02s |

### 구조
- 발화 A가 재생되는 동안 백그라운드에서 다음 턴(화자선정→대사→합성)을 완성해 둔다.
- 유저 개입 시 폐기 후 실시간 경로로 반응 (비용: LLM+TTS 1회 낭비).
- 재생 페이스는 FE played ack 기반 — 서버가 재생보다 앞서 달리지 않음.

### 관찰
- **준비 지연이 재생 시간 뒤에 숨어 체감 0에 수렴** — PRD가 "이 구조만의 이점"으로 예고한 그대로.
- 2.88s 케이스는 v3 합성이 재생(3s 가정)보다 오래 걸려 일부 노출된 것 — 발화가 길수록 재생도 길어져 자연 상쇄되는 경향.
- 남은 간격의 대부분은 의도된 유저 발언 틈(radio 1.5s) — 티키타카 리듬 튜닝 변수.

### 다음
- 유저 발화 → 첫 응답 지연(끼어들기 경로) 측정 — prefetch가 안 먹는 구간, §3.1 예산 대상.
- 세션 단위 p50/p95 자동 수집(Langfuse trace) 및 턴당 비용 병기.

## 2026-08-26 — 유저 응답 경로의 한계 (실사용 발견, Phase 3 착수 근거)

push-to-talk 실사용에서 "말해도 바로 전달이 안 되는 느낌" 확인. 원인 분해:

| 구간 | 지연 | 비고 |
|---|---|---|
| 버튼 뗌 → 전사 완료(whisper) | ~1s+ | 이 동안 화면 무반응 — 인지된 지연 가중 |
| supervisor + 발화 생성 | ~2s | |
| TTS(v3) 발화 통째 합성 | 2~4s | 최대 병목 |
| **합계 (버튼 뗌 → 첫 소리)** | **5~8s** | §3.1 예산(p95 < 1.5s) 대비 3~5배 초과 |

### 구조적 관찰
- **prefetch 비대칭**: AI끼리 턴은 미리 계산돼 ~2s 간격인데, 유저 응답 턴은 예측 불가라
  처음부터 계산 — 정작 유저가 말할 때 가장 느리다. prefetch로 못 푸는 정직한 지연.
- **반이중(push-to-talk)의 한계**: 발화가 끝나야 STT가 시작된다. 말하는 동안
  전사가 진행되는 스트리밍 STT 없이는 이 구간을 지울 수 없다.
- **발화 단위 TTS의 한계**: 문장 2개를 다 합성해야 첫 소리가 난다. 문장 단위로
  쪼개면 첫 문장 합성 시간만큼으로 단축 가능(§3.1 "문장 단위 flush").

→ 반창고(반응 필러 등)보다 구조 해법이 필요한 지점 — Phase 3 착수의 직접 근거.

## 2026-08-26 — Phase 3a: 문장 단위 TTS 스트리밍 (§3.1 "문장 단위 flush")

LLM 토큰 스트림에서 문장 경계를 실시간 감지, 첫 문장 완성 즉시 합성·전송.
둘째 문장은 첫 문장이 재생되는 동안 생성·합성(턴 내부 파이프라이닝).
문장 상한 도달 시 LLM 스트림 조기 중단(토큰 비용 절약) 덤.

| 지표 | 3a 이전 | 3a 이후 (실측) |
|---|---|---|
| 유저 say → 첫 오디오 | ~4-6s (발화 전체 생성+합성) | **~2.4s** (웜), 4.9s(콜드 1회) |

- 측정 3회 중 1회(0.00s)는 직전 턴의 잔여 문장 오디오가 겹친 잡음으로 제외.
- 남은 격차(목표 p95 < 1.5s): STT 시간(이번 측정은 텍스트 say라 미포함) + supervisor
  + 첫 문장 생성 + v3 합성(짧은 문장도 2~3s). 다음 지렛대는 3b(스트리밍 STT — 말하는
  동안 전사)와 응답 첫 문장의 저지연 TTS(flash) 검토.
