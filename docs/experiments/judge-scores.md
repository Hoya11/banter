# judge 점수 이력

시나리오 셋 채점 결과를 버전별로 누적한다. 각 행은 당시 프롬프트와 페르소나를 비교하고 다음 변경을 정하는 데 사용한 기록이다. 소규모 LLM judge 평가이므로 점수 상승을 일반적인 대화 품질 향상이나 사용자 만족도 향상의 증거로 단정하지 않는다.

GO/NO-GO는 프로젝트 내부 기준에 따른 판정이다. 반복 채점의 일치 여부는 평가 타당성이나 사람의 판단과의 일치 여부를 입증하지 않는다. 별도로 명시하지 않은 비교에는 통계적 유의성이나 신뢰구간이 계산되어 있지 않다.

## 2026-08-13 — judge 반복 일치 확인 (반복 채점 n=5, radio_silence)

### 결론
- 고정 대화 A를 5회 채점한 결과 모든 항목의 표준편차가 0이었다. 해당 모델·프롬프트·입력 조건에서 점수가 반복 일치했다는 뜻이며, 모든 입력에서의 결정성이나 평가 타당성을 입증하지는 않는다.
- 시나리오 B를 5회 실행한 결과도 user_inclusion이 모두 5여서 내부 기준상 NO-GO였다. 직전 1회의 8은 이번 반복에서 재현되지 않았지만, 통계적 이상치이거나 잘못된 점수라고 확정할 근거는 없다.
- 단일 GO를 일반화하기보다 반복 결과를 함께 보고 판단을 보류해야 함을 확인했다. 점수의 적절성을 판단하려면 실제 대화 검토와 사람의 평가 등 별도 근거가 필요하다.
- 부수 발견: judge가 overall_comment를 scores 안에 넣는 구조 오류가 있었음 → 파싱 복구 + 반복 채점 실패 격리로 대응(fix).

### 정정 (2026-08-14 코드 검수에서 발견)
- **barge_in 시나리오의 GO 7.6은 끼어들기 수습 능력의 증거가 아니다.** harness의 `_interrupt`가 발화 텍스트를 자르지 않고 플래그만 달았고, judge 입력(`Turn`)이 그 플래그마저 버려서 judge는 완결 발화 뒤에 유저가 말하는 평범한 대화를 채점했다. 끼어들기 수습의 평가는 `_interrupt`의 텍스트 절단과 `Turn.interrupted` 전달을 구현한 뒤 다시 측정해야 한다.
