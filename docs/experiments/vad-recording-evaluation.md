# 녹음 파일로 VAD 비교하기

## 목적

같은 녹음에서 종료 침묵 설정을 바꾸며 감지 시작, 종료, 오감지, 놓친 발화와 중간 절단을
비교합니다. 설정을 조정할 때 결과를 반복해서 확인할 수 있도록 만든 로컬 평가 도구입니다.
라이브 마이크와 평가 도구는 `web/vad-capture.js`의 같은 발화 경계 판단 코드를 사용합니다.
평가 설정은 실제 서비스의 기본 설정이나 push-to-talk 모드를 바꾸지 않습니다.

실제 Silero v5 ONNX 모델을 로컬 CPU의 WASM으로 실행합니다. 마이크 권한, 서버 실행,
OpenAI 또는 ElevenLabs 키는 필요하지 않으며 외부 API를 호출하지 않습니다. 첫 의존성 설치는
npm 저장소에 연결하지만, 설치 후 평가에는 네트워크가 필요하지 않습니다.

이 도구의 시간은 녹음 파일의 샘플 위치입니다. 추론 계산 시간, 실제 발화에서 브라우저 재생
중단까지의 지연, 전사 지연이나 에코 품질을 측정하지 않습니다. 실제 대화에서 비교할 절차는
[VAD 끼어들기 실험](vad-interruption.md)에 별도로 유지합니다.

## 준비

프로젝트 루트에서 실행합니다. 이미 웹 의존성을 준비했다면 설치를 반복할 필요는 없습니다.

```bash
cd web
npm ci --ignore-scripts
npm run eval:vad -- --help
```

입력은 최대 5분, 128 MiB 이하의 WAV입니다. 16~96 kHz, mono 또는 stereo, PCM16/24/32와
IEEE float32를 지원합니다. WAVE_FORMAT_EXTENSIBLE, 압축 WAV, MP3는 지원하지 않으므로
일반 PCM WAV로 내보내야 합니다. 스테레오는 두 채널의 산술평균으로 변환합니다. 사용자와 AI를
다른 채널에 녹음했다면 평가하려는 마이크 채널을 따로 내보내세요. 볼륨 보정은 하지 않습니다.

실측 파일과 결과는 Git에서 제외한 프로젝트 루트의 `artifacts/vad-eval/`에 두는 것을 권장합니다.
도구는 원본 녹음을 복사하지 않습니다. 원본 파일은 삭제하거나 바꾸지 않고 보관합니다.

## 라벨 만들기

아래 명령은 `web` 디렉터리에서 실행합니다. 파일 경로는 자신의 WAV로 바꿉니다.

```bash
npm run eval:vad -- \
  --audio /absolute/path/recording.wav \
  --write-label-template ../artifacts/vad-eval/labels.json
```

양식에는 해당 WAV의 SHA-256과 다음 상태가 들어갑니다.

- `annotation_status: "unreviewed"`: 아직 검토하지 않은 상태입니다.
- `source_kind: "unverified"`: 입력 출처를 아직 기록하지 않았습니다.
- `utterances: []`: 발화의 정답 구간은 비어 있습니다. 무발화 정답을 뜻하지 않습니다.

녹음을 듣고 파형과 재생 위치를 확인해 `utterances`에 각 발화의 `id`, `start_ms`, `end_ms`를
넣습니다. 시간은 파일 시작부터의 밀리초이며 `id`는 중복되지 않는 문자열입니다. 발화는
시간순으로 넣고 서로 겹치지 않게 표시합니다. 형식은 다음과 같습니다. 아래 값은 형식 설명용이며
실제 녹음의 정답이나 측정 결과가 아닙니다.

```json
{"id": "u1", "start_ms": 1200, "end_ms": 3100}
```

라벨 단위는 한 번에 전달하려는 사용자 발화입니다. 문장 중간의 생각하는 침묵은 같은 발화
구간에 포함해야 해당 침묵에서 잘못 끝난 감지를 절단으로 평가할 수 있습니다. 주변 사람, TV,
AI 스피커 출력 등 참여 의도가 없는 소리는 정답 사용자 발화에 넣지 않습니다. 맞장구를 참여로
볼지도 녹음 전에 정하고 실험 메모에 남깁니다. 파일 전체를 검토할 수 없거나 화자를 구분할 수
없으면 `unreviewed`로 둡니다.

검토한 실제 녹음은 `source_kind: "recorded"`, 합성 음성이나 생성한 무음은 `"synthetic"`으로
표시합니다. 파일 전체의 의도된 발화를 표시했을 때만 `annotation_status`를 `"complete"`로
바꿉니다. 전체를 검토했으며 대상 발화가 정말 없는 소음 파일은 `complete`와 빈 배열로 나타냅니다.
다른 WAV의 라벨이나 파일을 수정하기 전의 라벨은 해시가 맞지 않아 거부됩니다.

## 비교 실행

```bash
npm run eval:vad -- \
  --audio /absolute/path/recording.wav \
  --labels ../artifacts/vad-eval/labels.json \
  --end-ms 400,600,800 \
  --out ../artifacts/vad-eval/run-001
```

`--end-ms`를 생략하면 400, 600, 800 ms를 비교합니다. 현재 라이브 기본값은 600 ms입니다.
나머지 시작 확인, 직전 버퍼, 최대 길이, 확률 임계값은 라이브 기본값으로 고정합니다. 설정된
침묵 시간은 32 ms 모델 프레임 단위로 올림하므로 각각 416, 608, 800 ms에 해당합니다.
이 값은 설정에 따른 판정 조건이며 달성한 사용자 체감 지연이 아닙니다.

`--labels`를 생략하거나 미검토 라벨을 사용해도 감지 구간은 확인할 수 있습니다. 이 경우
오감지율이나 지연 분포 등의 품질 지표는 `null`, 읽기용 표에서는 `미측정`으로 남습니다.
입력 출처를 synthetic으로 표시한 완성 라벨도 계산할 수 있으나 합성 입력 평가라고 기록됩니다.

결과 디렉터리는 새 경로여야 합니다. 같은 경로를 지정하면 기존 실험을 덮어쓰지 않고 오류를
알립니다. 다음 실행은 `run-002`처럼 다른 경로를 사용합니다.

## 결과 읽기

- `report.md`: 설정별 시작, 오감지, 놓친 발화, 중간 절단, 미완료와 취소 건수 및 지연 요약입니다.
- `report.json`: 전체 설정, 라벨, 발화별 대응, 비율의 분모, p50/p95/max와 재현 정보입니다.
- `frames.jsonl`: 각 모델 프레임의 원본 파일 끝 시각과 실제 모델이 반환한 발화 확률입니다.

결과에는 음성·라벨·모델·평가 코드의 해시, 의존성 버전, Node 버전, 운영체제와 CPU 아키텍처가
포함됩니다. 녹음 전체의 확률은 모델 상태를 유지하며 한 번 추론하고, 같은 확률을 각 설정에
입력합니다. 설정에 따른 판정 차이와 별도 추론 실행의 차이가 섞이지 않게 하기 위한 구성입니다.

감지 시작 확정이 라벨 구간 안에 있으면 그 발화와 대응시킵니다. 프레임 경계 때문에 발화 끝
직후에 확정된 경우는 32 ms까지만 허용하며 이 규칙을 결과에 저장합니다. 직전 오디오 버퍼의
겹침만으로 시작을 정답으로 인정하지 않습니다. 같은 발화에 두 번째 시작이 생기면 중복 시작으로
구분합니다. 하나의 긴 감지가 두 발화를 덮었다고 두 번째 시작을 만들어 세지 않습니다.

| 지표 | 계산 기준 |
| --- | --- |
| 오감지 시작 비율 | 어떤 대상 발화에도 대응하지 않는 시작 / 전체 감지 시작 |
| 놓친 발화 비율 | 대응하는 시작이 없는 대상 발화 / 전체 대상 발화 |
| 중복 시작 비율 | 같은 대상 발화에 추가로 생긴 시작 / 전체 감지 시작 |
| 중간 절단 비율 | 대응하는 감지가 라벨 종료 전에 침묵 종료 또는 최대 길이 취소된 발화 / 전체 대상 발화 |
| 시작 대기 | 대응하는 첫 시작 확정 시각 - 라벨 시작 |
| 종료 대기 | 대응하는 마지막 감지가 라벨 종료 이후 침묵으로 끝난 시각 - 라벨 종료 |

발화별 절단은 여러 번 생겨도 한 번만 셉니다. 최대 길이 취소는 별도 취소 건수에도 남습니다.
놓친 발화, 취소, 종료 판정 전에 파일이 끝난 발화를 성공한 지연 표본으로 넣지 않습니다.
지연은 사용 가능한 표본에 대해서만 계산하므로 건수와 실패 비율을 함께 봐야 합니다. 비율의
분모가 0이거나 유효한 지연 표본이 없으면 0으로 꾸미지 않고 `null`로 남깁니다.

입력 변환은 고정된 vad-web의 마이크 리샘플러를 사용합니다. 44.1 kHz처럼 모델 프레임과 정확히
나누어떨어지지 않는 입력도 실제로 소비한 원본 샘플 수로 시각을 계산합니다. 결과의
`effective_frame_thresholds`는 16 kHz 모델 프레임 기준이며 원본 녹음 시각과 조금 다를 수 있습니다.

파일 끝의 한 프레임 미만 잔여 입력은 버리고 길이를 `unprocessed_tail_ms`에 기록합니다.
침묵을 덧붙이거나 EOF를 종료 판정으로 사용하지 않습니다. 진행 중 발화는 `reason: "eof"`,
`end_ms: null`로 남기고, 아직 시작 확인 중인 후보는 `final_state: "candidate"`로 남깁니다.
마지막 발화의 종료 판단을 평가하려면 녹음에 발화 뒤 실제 침묵 구간도 포함해야 합니다.

## 현재 검증과 다음 판단

자동 테스트는 WAV 디코딩, 설정 비교, 수동 라벨 대응과 계산, EOF, 취소 및 기존 라이브 동작과의
동등성을 확인합니다. 테스트의 가짜 확률과 시간은 실제 감지 품질 수치가 아닙니다.
2026-09-08에는 기존 macOS 로컬 합성 음성 WAV를 실제 Silero 모델로 평가해 세 설정의 파일
출력을 확인했습니다. 수동 정답 라벨이 없으므로 품질 지표는 미측정으로 유지했습니다. 외부 음성
API와 실제 사용자 마이크를 사용하지 않았습니다.

실제 녹음과 완성 라벨이 준비되면 종료 대기와 중간 절단을 함께 비교합니다. 일부 파일에서
선택한 설정은 조정에 쓰지 않은 다른 녹음에서도 확인합니다. 현재 도구 실행 성공만으로 최적
설정이나 개선 비율을 정하지 않습니다. 실제 스피커 에코와 자동 끼어들기의 체감 평가는 별도
라이브 실험 후 판단합니다.
